# Графика «Танкороста»: 3D в стиле Clash Royale

**Статус: утверждено пользователем 2026-10-19** («все прекрасно»). Утверждены: стиль, танк игрока I, враг
«Игрушечный танк», препятствия ступени I, игрушки детской, живая сцена ступени I с отъездом камеры.
Предыстория выбора (пиксель-арт, изометрия, воксели — отклонены) — в `GAME_SPEC.md`, раздел «Графика».

## Стиль (не нарушать)

- **Как Clash Royale**: чистая сочная краска, крупные формы, «игрушечные» пропорции.
- **Свет нарисован в текстуре**: верх светлее, низ и грани вниз уходят в тень **со сдвигом оттенка**
  (жёлтый → оранжевый, красный → малиновый, металл → синий), а не в серый; выпуклые рёбра чуть светлее; углы мягко затенены.
- **Без потёртостей**: сколы, царапины, пятна, грязь — не делать (пользователю не понравились).
- **Рёбра острые, с ровной фаской в одну грань** (`segs=1`). Круглые многосегментные скругления — «мыльно», не делать.
- Металл синевато-серый, лёгкий глянец (roughness 0.3–0.45). Контура нет.
- Содержание — **из самой игры**, а не из старого AI-референса: никаких бластеров, светящихся кристаллов и синих огоньков.
  Враги, снаряды, препятствия — по `src/sim/content/enemies.ts`, `stages.ts`, `src/client/render.ts`.

## Инструменты

- Blender 5.2: `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe` (Python 3.13; GTX 1070 через CUDA — запекание на видеокарте).
- `scripts/lp.py` — библиотека модели: детали, фаски, раскраска, запекание, слияние материалов, экспорт .glb.
- `scripts/viewer.html` + `scripts/shot.mjs` — снимок модели в Three.js (как в игре).
- `scripts/scene_check.mjs` — снимки живой сцены на ×1/×4/×24, FPS, ошибки; `--csp` — проверка в условиях площадки артефактов.
- `scripts/glb2json.mjs` — `.glb` → glTF-JSON для публикации страницы.
- Playwright уже стоит в проекте. Локальная AI-генерация 3D на GTX 1070 (8 ГБ) не подходит — модели делаем скриптами.

## Цикл работы над моделью (не пропускать проверку глазами)

1. **Скрипт** `models3d/<имя>/build.py`:
   ```python
   import lp
   lp.reset()
   hull = lp.Part('hull')                                    # узел glb
   turret = lp.Part('turret', pivot=(x, 0, z), parent=hull)  # вращается вокруг pivot
   hull.box((sx, sy, sz), (x, y, z), 'yellow', bevel=.06, segs=1)   # брус (taper=(kx,ky), rot=)
   hull.prism([(x, z), ...], y0, y1, 'yellow', bevel=.07, segs=1)   # профиль XZ по Y — корпуса со скосами
   turret.frustum((bx, by), (tx, ty), z0, z1, 'yellow', loc=(x, 0, 0), chamfer=.42, bevel=.07, segs=1)
   turret.cyl(r, depth, (x, y, z), 'gunmetal', axis='x', segs=1)    # цилиндр/конус (r2=)
   P.sphere(r, loc, 'leaf', subdiv=2, scale=(1, 1, .85))            # икосфера; colors=f(центр грани)->цвет
   hull.torus(R, r, loc, 'gold', axis='x'); turret.star(R, loc, '+y', 'cream', ring=(ro, ri))
   lp.finish([hull, turret], HERE, '<имя>', bake=not NOBAKE)
   ```
2. **Сборка без запекания** (формы, ≈20 с): `"<blender.exe>" -b --factory-startup -P models3d/<имя>/build.py -- --nobake`
3. **Снимок**: `BG=grass DIST=10 EL=0.65 node .claude/skills/lowpoly-3d/scripts/shot.mjs <glb> out.png single soft`
   (`turn` — 4 ракурса; `MODEL2=<glb>` — пара рядом для сравнения размеров; `styles` — 3 варианта света).
4. **Посмотреть** и сравнить с образцом/референсом пользователя: силуэт, пропорции, читаемость сверху, детали.
5. Исправить, повторить; затем полная сборка с запеканием (≈30 с на модель) и снимки `turn` + `single` + пара с танком игрока.
6. Показать пользователю на зелёном поле (`BG=grass`) и ждать правок — он смотрит каждую модель.

## Правила моделей

- Оси Blender: X — нос, Y — левый борт, Z — вверх; glTF переводит в Y-up, нос остаётся +X (в игре `rotation.y = -heading`).
- Масштаб: 1 = 1 м мира. **1 px игры ≈ 4/28 м** (танк 28 px ≈ 4 м). Танк I ≈ 4.0 × 2.6 × 2.7 м; враги-игрушки ≈ 0.75 танка.
- Пропорции «игрушки»: короткий высокий корпус, крупная башня, толстый ствол, крупные катки; верх гусениц виден.
- Цвета — только из `PALETTE` в `lp.py` (тройка c / hi / lo, lo сдвинут по оттенку) + `EMISSIVE` для фар/фонарей.
- Фаски одной гранью: корпуса и башни 0.05–0.07, средние 0.03–0.05, мелкие 0.015–0.025. Цилиндры 14–18 граней, мелочь 6–10.
  Мелкий шум (заклёпки рядами) не плодить.
- Всё крепимое (антенны, ящики, фары) — **на поверхность**: основание лежит на грани, а не над скосом.
- Гусеницы: траки внахлёст (`длина = периметр / n * 1.06`) — лента без просветов; 4 катка стоят на нижней ветви
  (низ катка = внутренняя поверхность трака), между собой и с концами ленты не пересекаются. Ведущее колесо/ленивец не ставить.
- Вращающиеся в игре детали (башня, ствол, винт) — отдельные `Part` с `pivot`.
- Светящееся (`lamp`, `lamp_red`) не запекается, экспортируется как emissive.
- После запекания `lp.merge_slots` сливает одинаковые материалы — в glb один кусок краски (+ огни). Не ломать: сцена делает
  по InstancedMesh на кусок, лишние куски = лишние вызовы отрисовки на телефоне.
- Бюджет: танк ≤ 15k треугольников, краска 1024² на узел (мелочь 512²). Для игры — сжать (gltf-transform, WebP/KTX2).
- Запекание (`_bake_tree`): градиент по высоте детали (Generated Z), тень по нормали вниз → `lo`, верх → `hi`,
  светлый край (AO «изнутри», 0.12 м), углы AO 0.4 м цветом `lo`. Меняешь — пересобери образцы и сравни снимки.

## Сцена уровня (образец — `docs/scene-t1/index.html`, утверждена)

- **Раскладка — из кода игры** (`toyProps` в `src/sim/content/stages.ts`): ячейки 144 px (≈20.6 м), те же модули и вероятности,
  зеркальная симметрия по четвертям, пустой старт, укрытия у старта. Пересчёт px → м через 4/28.
  Кусты и пруды в игре редкие (5% и 3%) — для показа можно задать их в нескольких четвертях явно, сказав об этом.
- **Земля арены**: клетки 6 м двух зелёных (`#7fc94c` / `#76c044`) с мягкими пятнами — как арена Clash Royale;
  песчаная тропинка (`#e3c48d`/`#efd6a6`); пучки травы — InstancedMesh из конусов. Вода прудов — над землёй (y ≈ 0.05).
- **Песочница и детская** (видны при отъезде): деревянный бортик вокруг арены, пол из досок, круглый ковёр;
  игрушки ступени II в масштабе ×4 мира: кубик ≈ 23 м, карандаш ≈ 70 м, мяч ≈ 30–45 м, книга ≈ 70 м.
- **Камера**: перспектива fov 30, азимут 45°, высота 55°, дистанция `50 × zoom` м. ×1 — бой, ×4 — вся ступень,
  ×24 — арена в детской; цель плавно уходит от танка к центру начиная с ×2.5. Отъезд — сценарий 1 → 4 → 24 → 1.
- **Свет**: Hemisphere `#e6eeff`/`#4a3f3a` 1.1 + Directional `#fff3df` 3.3 сверху-слева, мягкие тени (рамка тени
  `22 × zoom + 12`), NeutralToneMapping, экспозиция 1.12. Туман по дистанции камеры (`near = dist × 1.6`).
- **Свечение (bloom) — только для вспышки выстрела**: порог 4.0. Огонь — насыщенный оранжевый без пересвета
  (множитель цвета 1.4–1.6), иначе огонь розовеет, а на ×24 вся картинка блёкнет.
- **Эффекты**: снаряд — светлая капсула с жёлтым носиком и белым дымным следом; вспышка у ствола; взрыв —
  оранжевые шарики огня, белые клубы дыма, обломки цвета врага, бледная подпалина на траве; попадание в блок — песочная пыль.
- **Препятствия** — InstancedMesh на каждый кусок модели, поворот блоков кратно 90°; модели загружаются один раз.
- Проверка: `node .claude/skills/lowpoly-3d/scripts/scene_check.mjs <page.html> <папка> --csp` — 60 FPS, «ошибок нет».

## Показ на опубликованной странице (артефакт claude.ai)

Площадка не отдаёт `.glb` и запрещает странице `fetch` по `data:` и `blob:`. Рабочая схема (как в `docs/scene-t1/index.html`):
1. `node .claude/skills/lowpoly-3d/scripts/glb2json.mjs models3d/... --out docs/<страница>/models` — glTF-JSON со встроенным буфером.
2. На странице: `fetch('models/x.json')` → `atob` → собрать GLB в памяти → `GLTFLoader.parse(arrayBuffer)` (функция `load` в образце).
3. На время загрузки `window.createImageBitmap = undefined` — текстуры идут через `<img src=blob:>` (разрешено), а не через `fetch`.
4. Публиковать страницу с `files: {"models/x.json": "docs/<страница>/models/x.json", ...}`; проверять `scene_check.mjs --csp`.
